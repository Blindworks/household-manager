- **Concurrent-agent git commit recipe that actually worked:** a parallel backend agent was committing to `backend/` in the same working tree/index at the same time. `git add` only my frontend paths, then `git status` showed backend files already staged by the other agent (they add/commit externally, outside my control) — committing "the index as-is" would have bundled both agents' work into one commit. Fix: `git commit -m "<msg>" -- <frontend paths...>` — pathspec-limited commit only touches the listed files' staged changes, leaving the other agent's staged backend files untouched for their own commit. **Order matters**: `-m` must come before `--`; `git commit -- <paths> -m "msg"` fails because everything after `--` (including `-m` and the message string) is parsed as a pathspec.
